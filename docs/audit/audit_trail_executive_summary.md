## 一、业务背景

QRS 项目是一个基于 dbt 的制药质量管理数据仓库，涵盖 ERP、MES、LIMS、QMS、PV、SCADA 六大业务系统。为满足 GMP 合规要求和数据质量保障需求，需要建立完整的审计跟踪系统。

### 核心需求

1. **状态变更审计**: 追踪关键业务数据的历史变更（如订单状态、检验状态、变更控制状态）
2. **逻辑迁移审计**: 验证从旧系统迁移到 dbt 模型的数据一致性
3. **合规性要求**: 满足 GMP 对数据可追溯性的要求（7 年数据保留）

│           │  - 性能监控       │                         │

### 2.2 核心技术栈

| 组件 | 技术选型 | 版本 | 用途 |
|------|---------|------|------|
| 数据库 | PostgreSQL | 13+ | 数据存储 |
| 转换工具 | dbt Core | 1.10+ | 数据转换 |
| 快照功能 | dbt Snapshots | 内置 | SCD Type 2 实现 |
| 审计包 | audit_helper | 0.12.2 | 数据对比验证 |
| 工具包 | dbt_utils | 1.1.1 | 通用工具 |

### 2.3 实施范围

#### 状态变更审计（7 个快照表）

| 快照表 | 源表 | 追踪字段 | 运行频率 | 优先级 |
|--------|------|---------|---------|--------|
| snap_purchase_orders | stg_purchase_order | order_status | 每日 | 高 |
| snap_material_receipts | stg_material_receipt | inspection_status | 每日 | 高 |
| snap_inspection_requests | stg_inspection_request | request_status | 每 4 小时 | 高 |
| snap_inspection_tasks | stg_inspection_task | task_status | 每 4 小时 | 高 |
| snap_change_controls | stg_change_control | change_status | 每日 | 高 |
| snap_deviations | stg_deviation | deviation_status | 每日 | 高 |
| snap_capas | stg_capa | capa_status | 每日 | 高 |

#### 逻辑迁移审计（3 个核心模型）

- 采购订单数据对比（行级 + 列级）
- 检验请求数据对比（行级 + 列级）
- 变更控制数据对比（行级 + 列级）

## 三、关键特性

### 3.1 快照功能特性

✅ **SCD Type 2 实现**
- 完整的历史记录追踪
- 自动维护有效期（valid_from / valid_to）
- 硬删除记录追踪（is_deleted 标记）

✅ **性能优化**
- timestamp 策略（性能最优）
- 部分索引（当前记录查询 < 100ms）
- 复合索引（历史查询 < 500ms）

✅ **数据质量保障**
- 主键唯一性测试
- 时间逻辑验证
- 自动化质量检查

### 3.2 审计功能特性

✅ **行级对比**（compare_queries）
- 整体数据一致性验证
- 快速获得匹配率
- 识别缺失记录

✅ **列级对比**（compare_column_values）
- 精确定位差异列
- 7 种差异状态分类
- 支持增量审计策略

✅ **数据标准化**
- 时区统一（UTC）
- 精度统一（2 位小数）
- NULL 值处理标准化

## 四、实施计划

### 4.1 时间线

```
阶段 1: 基础设施准备  (Week 1-2)
  ├─ 包安装与配置
  ├─ Schema 创建
  ├─ 核心宏开发
  └─ 目录结构搭建

阶段 2: 快照实施      (Week 3-5)
  ├─ 高优先级快照 (3个)
  ├─ 中优先级快照 (4个)
  └─ 性能优化与测试

  ├─ 行级审计 (3个模型)

阶段 4: 生产化        (Week 9-10)

  ├─ 监控部署
  └─ 团队培训

```
