## H3：统一质量事件事实表（P3）实现说明

### 1. 业务目标与指标口径

**目标**：将偏差（Deviation）、CAPA、投诉（Complaint）、召回（Product Recall）、变更控制（Change Control）统一为可汇总、可关联、可追溯的事件口径，满足 PQR 事件统计与跨域关联分析需求。

**统一分析维度（核心字段）**

- 事件类型：`event_type`
- 事件状态：`status_code`（closed / in_progress / pending / unknown）+ `is_closed`
- 风险等级：`risk_level_code`（critical / high / medium / low，来自映射）
- 根因分类：`root_cause_category_code`（人机料法环测，来自映射）
- 关联键：`batch_number`、`product_id`（可用则填）
- 生命周期：`create_date`、`close_date`、`cycle_time_days`

### 2. 分层与数据来源

为满足“seed → staging → business”的分层引用约束，H3 的数据链路采用 seed 作为原子输入（开发环境可直接 `dbt seed` 复现），并由 staging 清洗后输出 business 语义层。

**seed（原子数据）**

- QMS：`qms_deviation`、`qms_capa`、`qms_change_control`
- PV：`pv_complaint`、`pv_product_recall`
- 标准化映射（H3新增）：
  - `quality_root_cause_categories`：根因分类维表
  - `quality_root_cause_mapping`：根因文本映射规则
  - `quality_risk_levels`：风险等级维表
  - `quality_risk_mapping`：风险字段映射规则

**staging（清洗/标准化）**

- 事件清洗：
  - `stg_quality_event_deviation_seed`
  - `stg_quality_event_capa_seed`
  - `stg_quality_event_change_control_seed`
  - `stg_quality_event_complaint_seed`
  - `stg_quality_event_product_recall_seed`
- 映射清洗：
  - `stg_quality_root_cause_categories`、`stg_quality_root_cause_mapping`
  - `stg_quality_risk_levels`、`stg_quality_risk_mapping`

**business（最终业务视图）**

- `dim_root_cause_categories`
- `dim_risk_levels`
- `fct_quality_events`

### 4. 更新频率与运维建议

- seed：按需更新（由数据治理/质量团队维护映射规则与字典，或由源系统导出刷新）
- staging/business：随 `dbt run` 刷新；`fct_quality_events` 建议在生产环境按业务窗口每日/每小时运行（视源系统同步频率）

### 5. 校验与测试

- schema tests：主键唯一性、非空、枚举值、维表关系（对可映射字段做条件 relationships）
- singular tests：`assert_batch_process_parameters_oos_points_valid` 为 H2 已新增；H3 目前依赖 schema tests 覆盖事件口径与映射一致性
