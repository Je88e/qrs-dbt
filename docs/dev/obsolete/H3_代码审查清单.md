## H3：统一质量事件模型代码审查清单

### 1. 分层与引用约束

- staging 模型仅 `ref()` seed（无 `source()`，无跨层级引用）
- business 模型仅 `ref()` staging（不直接引用 seed / source / business）
- 单元测试已覆盖：运行 `python scripts/test_h3_layering.py` 应为 OK

### 2. 模型口径与业务一致性

- `fct_quality_events` 是否覆盖偏差/CAPA/投诉/召回/变更五类事件
- `event_id` 生成逻辑是否稳定（source_system + event_type + source_event_id）
- `status_code/is_closed` 规则是否满足业务口径（需确认状态枚举覆盖）
- CAPA 是否按 `source_type/source_id` 正确回补关联偏差的 `product_id/batch_number`
- 召回 `batch_numbers_raw` 与 `batch_number`（split_part 取首个）是否满足当前分析需求

### 3. 映射规则与维度表

- `quality_root_cause_categories` 是否满足“人机料法环测”字典口径
- `quality_root_cause_mapping` 规则优先级（priority）是否合理，contains/equals 是否符合预期
- `quality_risk_levels` 与 `quality_risk_mapping` 是否覆盖投诉优先级/变更优先级/召回等级映射
- `dim_root_cause_categories`、`dim_risk_levels` 是否只作为标准化字典输出（不引入额外业务逻辑）

### 4. 文档与血缘

- staging 与 business 的 schema.yml 是否包含关键字段说明与核心测试
- [H3_统一质量事件模型说明.md](file:///mnt/d/Work/NovaTech/QRS/dbt/docs/H3_%E7%BB%9F%E4%B8%80%E8%B4%A8%E9%87%8F%E4%BA%8B%E4%BB%B6%E6%A8%A1%E5%9E%8B%E8%AF%B4%E6%98%8E.md) 是否清晰描述口径、来源、更新频率与依赖图谱
- `dbt docs generate` 是否可生成并在 catalog/manifest 中体现依赖链路

### 5. 运行与测试门禁（建议作为合并条件）

- `dbt seed --select quality_* --full-refresh` 成功
- `dbt run --select fct_quality_events` 成功
- `dbt test --select fct_quality_events` 成功
- 映射维表关系测试：`risk_level_code/root_cause_category_code` 有值时必须能关联到对应 dim
