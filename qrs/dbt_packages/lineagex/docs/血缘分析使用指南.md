# 数据血缘分析使用指南

## 📖 概述

lineagex 包为 QRS 项目生成完整的数据血缘分析，包括表级和列级血缘关系。

**核心输出文件**:
- `output.json` (210 KB) - 血缘数据（JSON 格式）
- `index.html` (210 KB) - 交互式血缘可视化页面

**覆盖范围**:
- 92 个 dbt 模型（staging, intermediate, dimension, fact, snapshot）
- 44 个源表（来自 6 个源系统：ERP, MES, LIMS, QMS, SCADA, PV）
- 总计 136 个表/模型的完整血缘关系

---

## 🚀 快速开始

### 1. 生成血缘数据

```bash
cd qrs/dbt_packages/lineagex
python3 main.py
```

**执行时间**: 约 2-5 分钟（取决于模型数量）

**输出**:
- `output.json` - 血缘数据
- `index.html` - 可视化页面

### 2. 查看可视化结果

在浏览器中打开 `index.html`，可以：
- 查看完整的血缘图
- 点击节点查看列级血缘
- 搜索特定的表或列
- 过滤特定的数据流路径

## 📊 output.json 文件结构

### 基本结构

```json
{
  "表的唯一标识符": {
    "table_name": "schema.table_name",
    "tables": ["直接依赖的上游表"],
    "columns": {
      "列名": ["该列的来源列"]
    },
    "upstream_tables": ["所有上游依赖"],
    "downstream_tables": ["所有下游依赖"],
    "is_model": true/false
  }
}
```

### 字段说明

| 字段 | 说明 | 示例 |
|------|------|------|
| `table_name` | 表的完整名称 | `"public.fct_adverse_events"` |
| `tables` | 直接依赖的上游表 | `["raw.pv_adverse_event"]` |
| `columns` | 列级血缘映射 | `{"event_id": ["stg_adverse_event.event_id"]}` |
| `upstream_tables` | 所有上游依赖（递归） | `["raw.pv_adverse_event", "model.qrs.stg_adverse_event"]` |
| `downstream_tables` | 所有下游依赖 | `["model.qrs.pqr_summary_report"]` |
| `is_model` | 是否为 dbt 模型 | `true` (模型) / `false` (源表) |

## 💡 实际应用示例

### 示例 1: 影响分析

**场景**: 需要修改 `raw.lims_analyst` 表结构，想知道会影响哪些下游模型。

**方法**:
```python
import json
data = json.load(open('output.json'))
affected = data['raw.lims_analyst']['downstream_tables']
print(f"将影响 {len(affected)} 个表:")
for table in affected:
    print(f"  - {table}")
```

**输出**:
```
将影响 3 个表:
  - model.qrs.dim_analysts
  - model.qrs.fct_inspection_tasks
  - model.qrs.stg_analyst
```

### 示例 2: 列血缘追踪

**场景**: 想知道 `fct_adverse_events.processing_days` 这个列是如何计算的。

**方法**:
```python
sources = data['model.qrs.fct_adverse_events']['columns']['processing_days']
print(f"processing_days 来源于:")
for source in sources:
    print(f"  - {source}")
```

**输出**:
```
processing_days 来源于:
  - stg_adverse_event.close_date
  - stg_adverse_event.report_date
```

**解读**: 这是一个计算列，由两个日期列计算得出（处理天数 = 关闭日期 - 报告日期）。

### 示例 3: 完整数据流追踪

**场景**: 追踪数据从源表到最终报表的完整路径。

**方法**:
```python
def trace_upstream(table_name, data, depth=0):
    """递归追踪上游依赖"""
    indent = "  " * depth
    print(f"{indent}└─ {table_name}")
    
    upstream = data.get(table_name, {}).get('upstream_tables', [])
    for up in upstream:
        if up and up != '':
            trace_upstream(up, data, depth + 1)

trace_upstream('model.qrs.pqr_summary_report', data)
```

**输出**:
```
└─ model.qrs.pqr_summary_report
  └─ model.qrs.fct_adverse_events
    └─ raw.pv_adverse_event
  └─ model.qrs.fct_complaints
    └─ raw.pv_complaint
```

## 🔍 高级查询

### 查找复杂计算列

```python
# 查找来源于多个列的计算列
complex_columns = []
for table, info in data.items():
    if not info.get('is_model'):
        continue
    for col, sources in info.get('columns', {}).items():
        if len(sources) >= 2 and sources != ['']:
            complex_columns.append({
                'table': table,
                'column': col,
                'sources': sources
            })

print(f"找到 {len(complex_columns)} 个复杂计算列")
```

### 查找终端表（没有下游依赖）

```python
terminal_tables = [
    table for table, info in data.items()
    if info.get('is_model') and not info.get('downstream_tables')
]
print(f"终端表: {terminal_tables}")
```

### 查找源表（没有上游依赖）

```python
source_tables = [
    table for table, info in data.items()
    if not info.get('is_model')
]
print(f"源表数量: {len(source_tables)}")
```

## ⚙️ 技术原理

### 血缘数据生成流程

1. **读取 dbt manifest** - 获取所有模型定义
2. **执行 EXPLAIN 查询** - 对每个模型执行 `EXPLAIN (FORMAT JSON)`
3. **解析查询计划** - 提取表和列的引用关系
4. **构建血缘图** - 生成表级和列级血缘
5. **计算上下游** - 递归计算所有依赖关系
6. **输出 JSON** - 保存为 `output.json`
7. **生成 HTML** - 创建交互式可视化页面

### 关键技术

- **PostgreSQL EXPLAIN** - 获取查询执行计划
- **JSON 解析** - 提取表和列的引用关系
- **图算法** - 计算传递闭包（上下游依赖）
- **列级血缘** - 通过查询计划的 Output 字段追踪列来源
